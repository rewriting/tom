# J4.1b — backend Go en Tom+Go (`Collector`, parcours `generate…`, générateur aplati, `tomgo suffix`) — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** porter en Tom+Go le backend Go du compilateur — la passe
`Collector` de `BackendPlugin`, le parcours `generate…`
d'`AbstractGenerator`, `GenericGenerator` et `GoGenerator` aplatis en un
seul type (spec §4.4) — et le brancher dans `tomgo suffix`, de sorte que
`tom -go --goFrom Backend` écrive, sur les 110 entrées de T1 et smoke, un
fichier identique octet pour octet à celui du backend Java (critère P2,
spec §5.1 et §6, ligne J4.1b).

**Architecture:** un nouveau paquetage `tom/engine/backend`
(`src/go/tom/engine/backend`) : le pilote `Generate` en Go pur
(`backend.go`, port de `BackendPlugin.run`), la passe `Collector` en
Tom+Go (`collector.t`), et le générateur aplati `goGenerator` réparti en
plusieurs `.t` du même paquetage, un par famille de méthodes. Les méthodes
pas encore portées sont des bouchons qui paniquent (`notported.go`) ; le
compteur P2 (in-process, `test/tools/j4`) compare la sortie de `Generate`
sur chaque paquet pont avec la sortie Java et compte les identiques par
famille ; chaque tâche porte une famille et relève le plancher du
compteur. L'état laissé par le `Collector` (marques « utilisé »,
inliners) est comparé à part avec Java (programme de test Java qui appelle
la méthode privée par réflexion), pour localiser un écart avant P2.

**Tech Stack:** Go 1.26+ (modules `tom`, `tomtools`), Tom+Go (`tom -go
-np`, mappings `adt.tom` et `sl.tom`, compilé par `mage regenTomGo` avec
`src/dist`), Tom+Java (`src/dist`, JDK 8), `mage` (`mage -d magefiles -w .
<cible>`).

Spec : `docs/superpowers/specs/2026-10-24-j4-tom-go-compiler-design.md`
(§3.1 table et marques, §4.4 structure du code porté, §5.1 P2, §5.3
budget, §5.4, §6 ligne J4.1b, §7 risques, §8 D4–D5). Jalons précédents :
`doc/go/j4-0-report.md`, `doc/go/j4-1a-report.md` (sous-ensembles
`OutputCode`/`SymbolTable`/`TomBase` portés : plan
`docs/superpowers/plans/2026-10-24-j4-1a-foundations.md`, section
« Sous-ensemble porté »). Revue finale de J4.1a :
`.superpowers/sdd/progress.md` (fin de la section J4.1a).

## Global Constraints

- **Décisions (spec §8)** : D4 `src/dist` compile le Tom+Go (`mage
  regenTomGo`, garde de fraîcheur) ; D5 le côté Go ne cible que Go : les
  branches et classes des autres cibles (`CGenerator`, `JavaGenerator`,
  `jCode`, `cCode`, `inline` du C/Java…) sont **omises**, avec un
  commentaire `// Java: … (D5)` à l'endroit omis ; les sources Java restent
  intactes.
- **`src/` ne contient que des sources** : les `X.t.go` générés sont
  ignorés par git dans `src/` et copiés dans l'amorce `stable/go/tom` par
  `mage -d magefiles -w . promoteGo`, puis `bootstrap`. Chaque tâche qui
  touche un `.t` ou un `.go` de `src/go/tom` finit par `regenTomGo`,
  `promoteGo`, `bootstrap` et committe `stable/go/tom` : un clone neuf doit
  continuer de se construire sans Java (`tomgo` importe le backend). La
  promotion du backend comme compilateur de référence et P3 (self-T1) sont
  J4.1c, hors de ce plan.
- **`legacy/` n'est jamais modifié.** `src/tom/` n'est modifié que pour le
  relais des lignes `INFO` par `GoBridgePlugin` (Task 3) et pour corriger
  un défaut de `-go` (voir « Risques et conditions d'arrêt ») ; chaque
  modification de `src/tom/` est suivie de `./build.sh src.dist` et de T0
  (`mage … portJava`, planchers inchangés).
- **Comptes de référence, inchangés à la fin du jalon** : T0 `102/764`
  (défaut) et `103/765` (`-np`), planchers `minDefault = 102`, `minNP =
  103` ; tableau de bord T2 `77 OK / 11 OK (diagnostics) / 9 échoue dans
  legacy / 2 non supporté / 4 support / 0 divergence / 0 non porté` ; T3 16
  lignes, 0 non couverte ; `bridgeCheck` : 110 paquets, `String()`
  identique `1139 / 1139`, requêtes `SymbolTable`/`TomBase` 110 / 110 ;
  `TestOutputCodeJava` 407 / 407 ; **goldens T1 inchangés** (ils sont
  l'oracle de P2 : ne jamais lancer `-update`).
- **Compteur P2** (Task 3) : il ne baisse jamais ; chaque tâche de famille
  relève ses planchers (`minIdenticalJ4`, `minIdenticalBridge` dans
  `test/tools/j4/backend_test.go`) à la valeur mesurée, et la reporte au
  tableau de bord `doc/go/j4-dashboard.md`. Un plancher ne se relève
  qu'après mesure ; il ne se baisse jamais pour « faire passer ».
- Toujours `unset TOM_HOME` avant `./build.sh` ou un `bin/tom`. JDK 8 pour
  construire (`java -version` → `1.8.0_…`) et pour les programmes Java de
  test.
- **Binaires périmés** : toute modification de `src/go/tom/**/*.go` (y
  compris un `X.t.go` régénéré) rend `src/dist/bin/{gomgo,tomgo}` plus
  anciens que leurs sources ; `CheckFresh` fait alors échouer les harnais.
  Avant eux : `unset TOM_HOME && ./build.sh src.dist`.
- **Style du port (spec §4.4)** — règles R1–R10, valables pour toutes les
  tâches :
  - **R1 aplatissement** : un seul type `goGenerator` ; pour chaque
    méthode, on porte la version la plus dérivée sur le chemin Go
    (`GoGenerator`, sinon `GenericGenerator`, sinon `AbstractGenerator`),
    selon l'« Inventaire » ci-dessous, qui fait foi.
  - **R2 noms** : une méthode Java devient une méthode Go **de même nom**
    (initiale minuscule, non exportée : `generateInstruction`,
    `buildExpIsFsym`, orthographe Java conservée : `buildSubstract`),
    précédée de `// <nom> is <Classe>.<nomJava> (<Fichier>:<ligne>)` ; une
    méthode qui en masque une autre ajoute `, which masks <Classe>.<nom>
    (<Fichier>:<ligne>)`. Les fichiers Go suivent l'ordre des méthodes
    Java de leur famille.
  - **R3 surcharges** : la version `TomTerm` garde le nom, la version
    `BQTerm` prend le suffixe `BQ`, la version `Expression` le suffixe
    `Expr` (comme `tools.GetTermType`/`GetTermTypeBQ`/`GetTermTypeExpr`) :
    `getVariableName(TomTerm)`/`getVariableNameBQ(BQTerm)`,
    `getTermType`/`getTermTypeBQ`, `termType`/`termTypeBQ`.
    `instantiateTemplate` : la version à `deep` garde le nom, les deux
    autres deviennent `instantiateTemplateSubject` et
    `instantiateTemplateHeadTail`.
  - **R4 `super.`** : la méthode masquée est portée sous son nom suffixé
    par sa classe (`generateExpressionAbstract`, `generateBQTermAbstract`,
    `generateInstructionAbstract`, `getVariableNameAbstract`,
    `getVariableNameBQAbstract`, `buildGetSizeDeclGeneric`) et seul
    l'appel `super.x(…)` y renvoie ; tout autre appel va à la version la
    plus dérivée (appel virtuel Java).
  - **R5 paramètres** : mêmes paramètres et même ordre que Java, `deep
    int` et `moduleName string` compris ; `getSymbolTable(moduleName)`
    ignore son argument, comme en Java (`AbstractGenerator.t:67`,
    `BackendPlugin.t:237` : une seule table pour tous les modules).
  - **R6 sorties** : `output.write(String)` → `g.output.Write`,
    `write(int)` → `WriteInt(int64(…))`, `write(deep, s)` → `WriteDeep`,
    `write(deep, s, line, length)` → `WriteTL`, `writeOpenBrace`/
    `writeCloseBrace`/`writeComa` → mêmes noms en capitale ; un
    `StringBuilder s` devient un `strings.Builder` puis
    `g.output.Write(s.String())`. Les `IOException` disparaissent
    (`OutputCode` garde la première erreur, rendue par `Close`).
  - **R7 `null`** : une chaîne Java qui peut être `null` devient un couple
    `(string, bool)` quand la distinction avec `""` compte
    (`knownGoType`, `codomainGoType`, `expressionGoType`, `termType`), un
    pointeur `*string` pour un champ (`conditionalType`), `""` sinon
    (`currentClass`) ; un terme absent est `nil` (comme
    `tools.GetSymbolFromName`). Un template d'inliner (`getMake`…) se lit
    `template, ok := …` (J4.1a).
  - **R8 exceptions** : `throw new TomRuntimeException(m)` et
    `RuntimeException` → `panic(&platform.RuntimeError{Msg: m})` ; un
    `System.out.println` de diagnostic n'est **pas** porté (la sortie
    standard de `tomgo` porte le code) : `// port:` le signale ; le
    `catch(RuntimeException)` de `GoGenerator.termType` →
    `platform.CatchRuntime` ; les `VisitFailure` du `Collector` →
    `sl.ThrowVisitFailure()` (lancer) et erreur ignorée de `VisitLight`
    (`catch(VisitFailure) {}`).
  - **R9 termes** : un setter Java absent de l'API Go (`code.setCode(s)`)
    devient une reconstruction par backquote (`` `Code(ncode) ``) ; les
    variables de motif ne portent pas un mot-clé Go (`type` → `ty`, `var`
    → `v`) ; pas de littéral chaîne brut Go dans un `.t`.
  - **R10 code mort pour `-go`** : il est porté tel quel (par exemple
    `instantiateTemplate` sous `inline`, toujours faux avec `-go`,
    `GenericGenerator.t:72-74`) ; seules les branches des autres cibles
    sont omises (D5).
- Git : jamais `git add -A` ; indexer des chemins explicites et committer
  avec `git commit --only <chemins>` ; ne pas committer les fichiers non
  suivis connus (`.DS_Store`, `build.xml.bak*`, `tomgo/`) ; ne jamais
  toucher aux entrées de `git stash` ; pas de réécriture d'historique.
  Messages `tom-go J4.1b: <verbe> <objet>`, terminés par la ligne
  `Co-Authored-By` du modèle qui implémente (par exemple
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`). Un refus de
  permission : s'arrêter et le signaler.
- **Modèles** (politique de l'utilisateur) : Sonnet par défaut ; Opus
  pour la conception risquée (Tasks 1 et 2, justifiées dans leur en-tête)
  et la revue finale du jalon ; Haiku n'est pas employé (aucune tâche
  n'est une copie de code entièrement donné). Les vérifications longues
  (T0 ≈ 4 min, `portGo` ≈ 4 min, `bridgeCheck` ≈ 6 min, `backendCheck` ≈ 3
  min) sont lancées **une fois par tâche** par l'implémenteur, à la fin ;
  le contrôleur ne les relance qu'à la fin du jalon.

## Disposition retenue (et pourquoi)

- **Un paquetage `tom/engine/backend`** pour `tom.engine.backend`
  (spec §4.3), dans le module `tom` ; `cmd/tomgo` l'importe.
- **Pilote en Go pur** (`backend.go`) : `BackendPlugin.run` n'a pas de
  construction Tom. **`Collector` en Tom+Go** (`collector.t`) : c'est une
  `%strategy` avec `mu`/`TopDownCollect`.
- **Le générateur aplati est réparti par familles** dans plusieurs `.t`
  du même paquetage (D1 : préfixe `tom_<F>_` par fichier, J4.0b) :
  `generator.t` (type, constructeur, accesseurs, aides de type Go),
  `generate.t` (parcours d'`AbstractGenerator`), `declarations.t`
  (fonctions de mapping), `filtrage.t` (instructions et expressions du
  filtrage), `listes.t` (listes et tableaux), `strategies.t` (fonctions,
  `%strategy`, introspecteur, `%transformation` refusé). Chaque fichier
  reste lisible côte à côte avec sa source Java (R2).
- **Bouchons** (`notported.go`) : toutes les méthodes appelées par le
  parcours existent dès la Task 2 ; une méthode non portée panique avec
  `backend: <méthode> is not ported yet (J4.1b)`. Le compteur P2 lit ce
  nom pour localiser un cas non identique. La Task 7 supprime le fichier.
- **Deux compteurs P2.** (a) **in-process** (`TestBackendCorpus`,
  `test/tools/j4`) : `backend.Generate` sur chaque paquet `.tfix.bridge`,
  comparé à la sortie Java de la même compilation ; rapide, il sert de
  boucle de travail et de compteur par famille ; (b) **par le binaire**
  (`mage backendCheck`, Task 7) : T1 et smoke avec `TOMGO_GOFROM=Backend`,
  goldens T1 et sortie Java comparés octet pour octet ; c'est le critère
  de sortie du jalon.
- **État post-`Collector`** comparé avec Java (Task 1) : marques et
  inliners déterminent quelles fonctions de mapping sont émises et comment
  (`genDeclArray`, `isUsed…`) ; un écart y est localisé avant P2.

```go
// InlinerEntry is an entry of mapInliner (SymbolTable.t:559): Key is the
// prefix of the inliner followed by the name, Code the host code.
type InlinerEntry struct{ Key, Code string }

// InlinerEntries returns the inliners sorted by key. Java has no such
// accessor: the post-Collector dump (plan J4.1b) reads the field by
// reflection. port: sorted by bytes, Java's TreeMap by UTF-16 units (the
// same order on BMP text).
func (st *SymbolTable) InlinerEntries() []InlinerEntry {
	keys := make([]string, 0, len(st.mapInliner))
	for k := range st.mapInliner {
		keys = append(keys, k)
	}
	sort.Strings(keys)
	res := make([]InlinerEntry, len(keys))
	for i, k := range keys {
		res[i] = InlinerEntry{Key: k, Code: st.mapInliner[k]}
	}
	return res
}
```

```go
func firstLineDiff(got, want string) string {
	g, w := strings.Split(got, "\n"), strings.Split(want, "\n")
	for i := 0; i < len(g) || i < len(w); i++ {
		var gl, wl string
		if i < len(g) {
			gl = g[i]
		}
		if i < len(w) {
			wl = w[i]
		}
		if gl != wl {
			return fmt.Sprintf("line %d differs\nGo   %.300s\nJava %.300s", i+1, gl, wl)
		}
	}
	return ""
}
```

```java
/**
 * The state the Collector of BackendPlugin leaves (J4.1b,
 * test/tools/j4/collector_test.go; backend.CollectorDump writes the same
 * lines in Go): the used marks (getUsedKeyEntries), then the inliners
 * (mapInliner sorted by key). The private markUsedConstructorDestructor
 * and SymbolTable.mapInliner are reached by reflection.
 * Args: <outDir> <bundle>...; the k-th bundle (from 0) gives
 * <outDir>/<k>.txt in UTF-8.
 */
public class CollectorState {
  public static void main(String[] args) throws Exception {
    // the Collector prints "No moduleName in stack" on System.out: keep it out
    System.setOut(new PrintStream(new ByteArrayOutputStream()));
    for(int k = 1; k < args.length; k++) {
      String res = run(args[k]);
      Writer w = new OutputStreamWriter(new FileOutputStream(new File(args[0], (k-1) + ".txt")), "UTF-8");
      w.write(res);
      w.close();
    }
  }

  @SuppressWarnings("unchecked")
  static String run(String bundle) throws Exception {
    TomStreamManager sm = new TomStreamManager();
    SymbolTable st = sm.getSymbolTable();
    st.init(new StubOptionManager().set("goCode", Boolean.TRUE));
    Code code = null;
    BufferedReader in = new BufferedReader(new InputStreamReader(new FileInputStream(bundle), "UTF-8"));
    for(String line; (line = in.readLine()) != null; ) {
      int sp = line.indexOf(' ');
      String key = sp < 0 ? line : line.substring(0, sp);
      String rest = sp < 0 ? "" : line.substring(sp + 1);
      if(key.equals("used")) {
        KeyEntry ke = KeyEntry.fromString(rest);
        if(ke.isUsedSymbolConstructor()) {
          st.setUsedSymbolConstructor(ke.getSymbol());
        } else if(ke.isUsedSymbolDestructor()) {
          st.setUsedSymbolDestructor(ke.getSymbol());
        } else if(ke.isUsedSymbolAC()) {
          st.setUsedSymbolAC(ke.getSymbol());
        } else {
          st.setUsedType(ke.getTypedef());
        }
      } else if(key.equals("type")) {
        TomType t = TomType.fromString(rest);
        st.putType(t.getTomType(), t);
      } else if(key.equals("table")) {
        st.fromTerm(TomSymbolTable.fromString(rest));
      } else if(key.equals("code")) {
        code = Code.fromString(rest);
      }
    }
    in.close();
    BackendPlugin bp = new BackendPlugin();
    bp.setStreamManager(sm);
    Method mark = BackendPlugin.class.getDeclaredMethod("markUsedConstructorDestructor", Code.class);
    mark.setAccessible(true);
    mark.invoke(bp, code);
    StringBuilder out = new StringBuilder();
    for(KeyEntry ke : st.getUsedKeyEntries()) {
      out.append("used ").append(ke).append('\n');
    }
    Field f = SymbolTable.class.getDeclaredField("mapInliner");
    f.setAccessible(true);
    Map<String,String> inliner = new TreeMap<String,String>((Map<String,String>) f.get(st));
    for(Map.Entry<String,String> e : inliner.entrySet()) {
      out.append("inliner ").append(Quote.quote(e.getKey())).append(' ')
         .append(Quote.quote(e.getValue())).append('\n');
    }
    return out.toString();
  }
}
```

```go
package backend

import (
	"io"
	"time"

	"tom/engine/bridge"
	"tom/engine/platform"
	"tom/engine/tools"
)

// defaultDeep is BackendPlugin.defaultDeep (BackendPlugin.t:74).
const defaultDeep = 1

// Generate is BackendPlugin.run (BackendPlugin.t:110-173) on a bridge
// bundle: it writes on w the code Java's backend writes in the output
// file, and its diagnostics on r; ok is false when an error was reported.
// port: the encoding option and the output file are GoBridgePlugin's (it
// writes what tomgo prints); the PlatformException branch
// (platformStopped) has no Go counterpart: an option error is a runtime
// error here (platform.Options.SetReporter).
func Generate(b *bridge.Bundle, w io.Writer, r *platform.Reporter) (ok bool) {
	opts := platform.NewOptions(b.Options)
	opts.SetReporter(r)
	file := b.InputName
	ran := platform.Run(r, file, func() {
		if opts.Bool("noOutput") { // !isActivated() (BackendPlugin.t:233)
			r.Info(file, 0, platform.BackendInactivated)
			return
		}
		start := time.Now()
		output := tools.NewOutputCode(w, opts)
		if !opts.Bool("goCode") {
			// Java: CGenerator, CamlGenerator, PythonGenerator, AdaGenerator,
			// CSharpGenerator, JavaGenerator (D5)
			panic(&platform.RuntimeError{Msg: "no selected language for the Backend"})
		}
		st := tools.FromBundle(b)
		generator := newGoGenerator(output, opts, st)
		generator.setDeclPrefix(tools.GoDeclPrefix(b.InputName))
		pilCode := b.Code
		(&backendPlugin{st: st}).markUsedConstructorDestructor(pilCode)
		generator.generate(defaultDeep, pilCode, tools.DefaultModuleName)
		r.Info(file, 0, platform.TomGenerationPhase, int(time.Since(start).Milliseconds()))
		if err := output.Close(); err != nil {
			// Java passes one argument: {1} stays in the text
			r.Error(file, 0, platform.BackendIOException, err.Error())
		}
	})
	return ran && !r.HasError()
}
```

```go
// packageSources is the text of the hand-written sources of the package
// (.t and .go, generated .t.go and tests excluded).
func packageSources(t *testing.T) string {
	t.Helper()
	entries, err := os.ReadDir(".")
	if err != nil {
		t.Fatal(err)
	}
	var sb strings.Builder
	for _, e := range entries {
		n := e.Name()
		if strings.HasSuffix(n, ".t.go") || strings.HasSuffix(n, "_test.go") ||
			!(strings.HasSuffix(n, ".t") || strings.HasSuffix(n, ".go")) {
			continue
		}
		b, err := os.ReadFile(n)
		if err != nil {
			t.Fatal(err)
		}
		sb.Write(b)
	}
	return sb.String()
}
```
