# J2 — portage de test/ en Tom+Go — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** lever les défauts du parser îlot (`-np`) qui bloquent `-go`, puis porter `test/` en Tom+Go par lots, chaque cas validé contre `legacy/` (T2).

**Architecture:** inchangée (voir `doc/go/README.md`) ; corrections du compilateur dans `src/tom/`, runtime dans `src/go/tom/`, ports dans `test/go/<rel>`.

Spec de référence : `docs/superpowers/specs/2026-10-22-tom-go-backend-design.md` (règles de portage §4, T0–T3) et `2026-10-23-repo-layout-design.md` (emplacements).

## Global Constraints

- `-go` impose `-np` : tout défaut du parser îlot bloque la cible Go.
- T0 (sortie `--java` identique à `legacy/`, parser par défaut **et** `-np`) reste vert. Les entrées qui incluent des mappings générés par Gom sont compilées comme le fait `test/build.xml` : Gom de **chaque** distribution (legacy / actuelle) lancé d'abord dans un répertoire temporaire, puis `-I` vers ce répertoire ; elles deviennent ainsi de vraies comparaisons (et non deux plantages identiques). `npAllowed` reste vide sauf cas justifié.
- Règles de portage (inchangées) : `%match`, `%strategy`, `%gom`, motifs et backquotes identiques à l'original ; seul le code hôte Java devient Go ; `testFoo` → `TestFoo` ; ce qui est commenté reste commenté ; tout écart forcé marqué `// port:` ; un test impossible sans changement de conception → `// port: unsupported …` + entrée `Unsupported` ; un bug du compilateur se corrige dans `src/`, jamais dans le port.
- Chaque cas porté : entrée dans `cases`, golden (`-update`), oracle (`-update-oracle`, JDK 8 + `legacy/src/dist`), statut OK au tableau de bord.
- Après toute modification de `src/` : `unset TOM_HOME && ./build.sh src.dist` ; `mage -d magefiles -w . all` et `portJava` verts.
- Jamais `git add -A` ; commits `tom-go J2: …` + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` ; un refus de permission se signale.

### Tasks 3…N : portage par lots

Un lot = un sous-répertoire de `test/` (ou les fichiers racine restants). Ordre : `sl/` (bibliothèque de stratégies, prioritaire pour J3/J4), `gom/`, `antipatterns/`, `andor/`, `backquote/`, `rule/`, `numeric/`, `acmatching/`, `regress/`, fichiers racine restants.

Pour chaque lot :
- [ ] porter chaque `.t` fidèlement dans `test/go/<rel>` (code hôte Java → Go ; mappings Go manquants ajoutés dans `src/tom/library/mapping/go/` en suivant les mappings Java correspondants) ;
- [ ] tout échec de compilation `tom -go`, de build Go ou toute divergence T2 est d'abord diagnostiqué : bug du compilateur ou du runtime → corrigé dans `src/` avec une fixture gosmoke ; fonctionnalité non portée → `// port: unsupported` documenté ;
- [ ] `cases`, goldens, oracles, tableau de bord, `mage coverage` ; T0 vert ;
- [ ] commit par lot, avec dans le message le nombre de cas OK / unsupported.

Critère de fin de J2 : tous les fichiers de `test/` hors `error/` ont un statut autre que « non porté » ; le tableau de bord et `doc/go/coverage.md` sont à jour ; chaque `unsupported` a une raison.
